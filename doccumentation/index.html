Full-stack vehicle rental operations

Move every rental from reservation to return.

RentEaseLanka is an enterprise vehicle-rental and fleet-lifecycle platform for customers, fleet teams, drivers, and administrators. It brings discovery, verification, booking, handover, payments, inspection, maintenance, and reporting into one operational system.

What the platform delivers

One system. Every rental moment.

Business rules are enforced in the workflow, not left to manual follow-up. Every operational handoff has a corresponding state, validation, and audit trail.

◈

Identity & verification

Customers register and authenticate with JWT. NIC uploads enter a staff verification queue, and unverified customers cannot reserve vehicles.

  • BCrypt password hashing
  • Role-based route and method guards
  • Admin → Manager → Staff/Driver provisioning
▣

Fleet & categories

Managers maintain the fleet, category pricing, vehicle images, approval queue, and the full vehicle state lifecycle.

  • Multi-image vehicle uploads
  • Category and base-rate management
  • State Pattern transitions and filtering
◇

Bookings & estimates

Customers explore availability, calculate a rental estimate, and create collision-free reservations with optional chauffeur service.

  • Minimum one-day rentals
  • Temporal vehicle overlap checks
  • Automatic unpaid invoice and pickup deadline
↔

Pickup handover

Staff use a controlled three-step handover before a vehicle can be released and a booking becomes active.

  • Odometer and fuel capture
  • Pre-existing damage notes
  • Atomic handover, booking, and vehicle transitions
▤

Payments & deposits

The simulator supports invoice payments, idempotent transaction processing, security holds, damage charges, refunds, and audit logs.

  • Payment-method management
  • Deposit release and refund flow
  • Automated no-show cleanup
◷

Returns & maintenance

Return inspection, damage assessment, maintenance scheduling, and financial reporting close the operational loop.

  • Ending odometer and damage costs
  • Maintenance status and service history
  • Gross, cost, net revenue and utilization metrics

Technology stack

Modern, layered, container-friendly.

The stack separates the customer experience, REST business services, relational data, and deployment concerns for maintainability.

Frontend

React 18.3 + Vite 8

React Router, Axios, React Icons, React Toastify, responsive CSS, protected route layouts, and role-specific pages.

Backend

Spring Boot 4.1

Java 21, Spring MVC, Spring Security, Spring Data JPA, Bean Validation, layered Controller-Service-Repository architecture.

Persistence

Azure SQL Database

Managed Microsoft SQL Server-compatible storage for production data, accessed through JPA/Hibernate and the SQL Server dialect.

Security

JWT + BCrypt

Stateless signed tokens, role and verification claims, method-level authorization, and upload path sanitization.

Engineering

MapStruct + Lombok

Compile-time DTO/entity mapping and reduced Java boilerplate, with Maven annotation processing.

Web & delivery

Vercel + Render + Docker

Vercel hosts the React frontend, Render hosts the Spring Boot backend, and Docker provides a repeatable backend runtime.

Core lifecycle guardrails

  • Vehicle states: PENDING, AVAILABLE, RESERVED, RENTED, UNDER_MAINTENANCE, OUT_OF_SERVICE
  • Maintenance states: SCHEDULED, IN_PROGRESS, COMPLETED, CANCELLED
  • Booking completion requires payment, return inspection, and resolved deposit
  • Driver assignment uses date-time overlap detection

Production deployment

Vercel, Render, and Azure.

The production frontend is deployed on Vercel, the Spring Boot backend runs as a Docker-based Render service, and application data is stored in Azure SQL Database.

Deployment flow

  1. Build the React frontend and publish it to Vercel
  2. Build the Spring Boot backend using the project Dockerfile
  3. Deploy the container as a Render web service
  4. Configure the backend with the Azure SQL connection string
  5. Point the frontend API base URL to the Render service
  6. Keep secrets in platform environment variables

Runtime configuration

Production environment variables supply the Azure SQL URL, database username, database password, JWT secret, and server port. Secrets are intentionally not embedded in this documentation.
